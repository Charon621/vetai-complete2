# VetAI

当前版本项目逻辑与技术架构说明
多模态视觉模型 × 本地结构化 RAG × 规则护栏 × 微信云函数

---

## 1. 项目总览

当前 VetAI 已经不是“上传图片后直接调用一次大模型”的简单小程序，而是一套由 Qwen 多模态视觉模型、本地结构化知识库（RAG）、规则后处理、安全护栏和微信云函数共同组成的宠物皮肤病初筛系统。

系统的核心处理流程分为四个阶段：
第一阶段为前端病例采集与 ROI 患处裁剪，支持上传全景与特写照片；
第二阶段为微信云函数网关校验，执行身份鉴权、请求体积约束、服务端安全系统提示词注入与并发配额控制；
第三阶段为双阶段并行编排，轻量预检模型负责图像质控与客观形态学特征提取，深度诊断模型结合本地知识库候选生成结构化推断，若预检特征强命中本地知识库则触发 3～5 秒快速初筛通道；
第四阶段为确定性规则审查与安全护栏，执行非标 JSON 多级容错解析、物种与部位强排他规则过滤、红线分诊强制升级以及结构化报告渲染展示。

## 2. 用户实际使用时的处理流程

### 2.1 图片与病例信息采集
小程序首页支持直接调用已有宠物档案，也支持临时快速问诊。用户录入动物种类、性别、年龄、患处部位和主诉文本，并上传患处照片。系统支持将照片标记为整体、近景或参照角色。界面虽然保留了兔、仓鼠、鸟类等选项，但后端的医学规则与专科知识库以犬猫为核心。

### 2.2 上传图片与视觉输入约束
前端配置允许用户最多选择上传 5 张照片，但真正送入多模态视觉模型的图片数量上限被严格控制为 2 张。系统优先在全景图与患处细节图中挑选最关键的输入，其余图片仅保留在本地作为病例随访记录。这一设计兼顾了微信云函数的数据包体积、外部大模型调用成本以及网络传输响应时延。

### 2.3 患处圈选与 ROI 图像增强
用户在前端界面手动圈选患处病灶后，程序会在本地根据圈选坐标对病损区域执行 ROI（Region of Interest）裁剪与局部放大，并将裁剪后的特写图作为独立图像输入传递给视觉模型。患处圈选不仅是界面视觉标记，更直接为多模态模型提供了高清晰度的局部微观病理细节。

## 3. 双阶段并行诊断链路

### 3.1 Qwen3.8-Flash：视觉预检与特征提取
Flash 轻量模型不负责给出疾病诊断结论，而是把图像转化为受控词表下的客观形态学特征，包括圆形脱毛、鳞屑、表皮领圈、脓疱、黑头粉刺、红斑、结痂、局灶性分布、环形排列等形态描述。同时输出病灶可能部位、皮损分布范围、简要客观所见、图像质量等级以及可诊断性评分。

### 3.2 Qwen3.8-Flash：深度鉴别与综合分析
完整报告调用接收完整的病例基础资料与关键病损图片，负责生成结构化的辅助初筛分析，包括客观视觉观察、支持证据、反对证据、缺失待补充信息、候选疾病方向、主推方向、模型匹配分、建议排查项目、紧急程度评估以及家庭护理和线下转诊建议。

报告开启 medium 档思考，预检与问诊关闭思考；两者均使用阿里云 `qwen3.8-flash`，接口固定为 `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions`。

云函数使用阿里云 `QWEN_API_KEY` 环境变量，前端密钥字段保持空值；不再使用 DeepSeek 官网密钥。

### 3.3 并行调度机制
系统在用户提交初筛时同时发起视觉预检与完整诊断两条并发网络请求。预检调用关闭思考，用于快速提取特征，用于即时拦截模糊不可读图像，并探测是否满足本地知识库快速通道条件；完整报告调用则在后台持续推演深层病理关联。整体交互耗时显著收敛至单次完整调用的时延，避免了传统串行链路的双倍等待。

## 4. 图像质控与多级主动弃答机制

### 4.1 视觉预检层主动拦截
若 Flash 预检判定图像严重离焦模糊、曝光异常，或算法计算的可诊断性评分低于既定安全阈值，系统立即主动中断本次分析，并向用户明确说明图像质量缺陷，引导用户规范重新拍摄，不再浪费算力等待深度诊断。

### 4.2 完整提示词层证据弃答
在完整诊断提示词中严格预设了多项强制弃答触发条件：全部上传图像均不可读、病灶解剖边界完全无法辨识、最可能候选方向缺乏可交叉验证的客观形态证据、两项关键鉴别诊断之间缺失区分线索，或者该表征必须依赖线下细胞学镜检/组织病理学检查方能区分。

### 4.3 主动弃答的设计价值
通过在提示词与后处理层设置严格的弃答防线，系统从通用大模型“无论输入质量如何均强行猜测结果”的机械应答模式，转变为“证据不足时坦诚说明无法可靠判断”。对于面向家庭场景的动物医学初筛，这是保障临床安全边界与信任度的关键防线。

## 5. 本地专科知识库与轻量 RAG 架构

### 5.1 知识库架构特征
当前系统采用的 RAG（检索增强生成）范式并非通用的“外部长文档切割＋向量数据库向量相似度比对”，而是量身定制的“本地结构化疾病知识卡＋医学受控词表＋加权规则检索”轻量架构。

### 5.2 知识库规模与部署形态
知识库包含 65 种小动物常见皮肤疾病及细分表征条目，规则版本持续迭代至 v6 系列。全部数据与逻辑直接封装在前端 JavaScript 运行时中执行，无需依赖云端数据库读写，也不产生向量检索调用延迟。

### 5.3 疾病卡元数据构成
每张疾病知识卡均包含严密的字段结构：疾病标准名称、常用临床别名、适用动物物种、疾病分类归属、遗传易感品种、好发解剖部位、典型原发与继发皮损、特征性病史词条、复合表征规则、鉴别诊断要点、推荐排查检验、默认安全紧急度、居家护理规范、疾病从属层级、强排他规则、禁用归因条目、权威参考来源及审核版本。

## 6. 细粒度规则检索与偏置消除机制

### 6.1 多维综合加权计分
检索过程拒绝简单的字符匹配：视觉预检直接提取的规范皮损词赋予最高基础权重；主人主诉中呈现的视觉形态词、病史时间线、解剖部位、品种先验等分别赋予差异化权重；同时引入特征组合规则奖励加分与常见病发生率先验。

### 6.2 候选集合截断
规则检索执行完成后，算法对全库条目执行得分降序排列，仅筛选保留相关度最高的 Top 3 条目作为知识库候选输出，供下游模型提示词参考、来源溯源归因或快速初筛通道决策使用。

### 6.3 词表长度归一化
为防止关键词条目较多的长疾病卡在检索中天然占据不公平的得分优势，系统引入了症状词表长度归一化机制（K4 归一化），将实际条目长度带来的先验偏置严格抑制在安全区间内，保障罕见或特征集中型病种的合理召回。

---

## 7. 视觉形态词与临床病史词严格解耦

### 7.1 视觉词表
仅允许在静态图像中能够通过肉眼或皮肤镜直接识别的客观物理形态进入视觉受控词表，包括脱毛、鳞屑、脓疱、结痂、红斑、黑头粉刺、皮肤肿物、糜烂溃疡、局部渗出等。

### 7.2 病史词表
剧烈瘙痒、患处疼痛、季节性反复发作、频繁舔咬、体表异味、食欲减退、多饮多尿等无法直接从静态单帧照片中验证的关键信息，被物理隔离至独立的病史词表，且仅允许通过主人的口语主诉或病历问答渠道捕获。

### 7.3 解耦设计的临床价值
视觉大模型与知识库共享同一套高度标准化的受控视觉词体系，确保模型在图像中观察到的微观病变能够无损、无歧义地映射至兽医专科规则检索管线，有效阻断了因大模型自由发挥带来的同义词漂移与语义幻觉。

---

## 8. 视觉 RAG 快速初筛通道

### 8.1 快速通道触发逻辑
当 Flash 预检提取出的客观形态特征与本地知识库中某一疾病条目形成严密的高置信度强命中时（特征匹配得分达标、具备排他性特征组合且与第二候选存在显著分差），系统直接由知识卡数据装配输出高可靠性初筛报告，无需等待 完整诊断返回。

强命中判定对证据来源做了严格区分：检索命中会标记其来自视觉预检特征（照片侧）还是主诉文本，而强命中必须包含至少一个来自照片侧的非泛词特征命中。组合规则、疾病别名与主诉侧症状词都可能被主人的一段"教科书式描述"单独命中，唯独预检特征只能由照片产生——该底线保证快速报告永远有照片证据支撑，主人文字描述再完整也无法绕过看图直接领取一份具体病名报告。

### 8.2 工程收益
该机制使典型病例的端到端响应时延压缩至 3～5 秒，大幅降低了计算成本与接口网络开销，尤其适用于猫癣、急性湿性皮炎等形态极其典型的常见病例。

### 8.3 安全边界控制
快速通道虽然提升了响应时效，但客观上跳过了后续大模型的综合上下文权衡。因此快路径设计了极其苛刻的强命中门槛，目前代码中内置了专门的追踪监控，严控潜在的假阳性误触发；被快路径抢先丢弃的完整诊断调用也有独立埋点，用于核算快速通道的真实成本收益。

## 9. 完整诊断提示词的安全工程设计

### 9.1 角色定义与非诊断声明
完整诊断采用明确版本化的提示词工程。模型在系统角色中被严格限定为“兽医皮肤科初筛与就诊分诊辅助工具”，严禁给出具有法定处方权性质的确诊结论，明确要求提醒宠主以专业兽医线下体格检查为准。

### 9.2 严禁处方与剂量输出
系统级提示词设立了不可逾越的安全红线：严禁输出具体处方药物名称、使用剂量、用药频次、自行停药或换药方案；严禁出现“确诊、一定是、百分之百”等断言式表述。

### 9.3 证据链先于诊断结论
提示词在推理机制上强制遵循证据链结构：必须首先逐张评估输入图像的可读性，随后客观记录皮损表征，紧接着分别列出支持依据、反对依据、缺失病史线索与鉴别方向，最后才允许生成主推倾向。坚决杜绝大语言模型先产生直觉偏见、后倒推拼凑证据的幻觉漏洞。

### 9.4 规范 Few-shot 示例示范
提示词内嵌正反两类结构化示范样本：一类示范在病例资料详实、图片清晰时如何严谨推演鉴别诊断；另一类示范在图片模糊光照不良时如何规范执行主动弃答。在算法认知层面同时锚定“何时输出”与“何时拒答”。

## 10. 严格受控的结构化 JSON 通信

### 10.1 抑制自由文本输出
完整诊断结果被全面锁死为标准 JSON 语法格式，彻底封闭大模型的自由文本输出模式，从而在根本上保障了数据能被程序逻辑自动化解析、清洗、校验与标准化展示，消除模型胡言乱语与格式漂移的系统风险。

### 10.2 核心业务字段构成
输出字段包含图像可用性评估（imageFindings）、客观视觉所见（observations）、支持依据（evidenceFor）、反对证据（evidenceAgainst）、待补信息（missingInformation）、弃答原因（abstainReason）、候选疾病矩阵（diagnosisCandidates）、主推方向（primaryDiagnosis）、匹配评分（primaryDiagnosisProbability）、置信度评估（confidence）、建议排查项目（recommendedTests）、紧急度证据（urgencyEvidence）、分诊等级（urgency）、居家护理要点（homeCare）以及警示观察条件（whenToSeeVet）等。

## 11. 知识库作为参考上下文注入模型

### 11.1 完整病例上下文组装
大模型在接收推理请求时，会获取由前端结构化收集并清洗的宠物品种、年龄、性别、绝育状况、既往病史、患处解剖位置、主人主诉以及经过预检分类的图片上下文。

### 11.2 注入可信临床参考条目
若本地规则知识库检索出高度可信的相关疾病卡，程序会将最多 3 条参考信息附带其典型体征与鉴别要点以纯上下文形式注入提示词，为大模型提供高质量的专科参考锚点。

### 11.3 抑制模型锚定偏见
提示词中显式设置防锚定引导声明：明确告诫大模型注入的知识条目仅供内部临床参考，模型完全有权采纳、降级或全部推翻，严禁因为某疾病卡被检索召回就盲目将其置于首选位置。

## 12. 专科常见病防漏检安全覆盖网

### 12.1 覆盖网的设计目的
除了根据主诉召回的特定疾病外，系统额外在提示词中常驻维护了一份常见皮肤疾病清单，作为模型推理过程中的思维防漏兜底。

### 12.2 典型防漏检映射逻辑
当病变位于耳部时，强制提醒排查耳螨、马拉色菌性外耳炎与继发细菌感染；位于趾间爪部时，强制核验过敏性趾间炎与接触刺激；观察到圆形断毛伴鳞屑时，强制排查皮肤癣菌病；观察到丘疹脓疱伴表皮领圈时，强制核验浅表脓皮病。

### 12.3 安全界限
该清单明确定义为防漏检的安全扫描网，而非静态模板。模型必须根据该病例的实际客观事实做出判定，严禁机械式套用清单排序。

---

## 13. 模型输出后的确定性多层后处理管道

### 13.1 5 级 JSON 语法容错解析
系统依次启动 5 层容错引擎：常规标准解析、正则提取闭合 JSON 块、自动修复尾部悬空逗号、剥离外层 Markdown 代码围栏与剥离通用包裹字段。若 5 层机制全部失败，直接降级至安全兜底拒答，严禁将损坏的原始代码块暴露给用户。

### 13.2 专科医学排他规则过滤
模型返回的候选疾病列表必须经过前端知识库规则的二次硬性过滤，包括动物物种不符（如犬病模型误报给猫）、好发年龄不符、罕见部位冲突以及知识库内置的显式互斥规则。

### 13.3 候选重构与文本脱敏清洗
若排序第一的候选病种因违反排他规则被强制剔除，系统自动将通过审核的第二候选升格为主推；若所有模型候选均被规则安全否决，结果自动重置为无法可靠判断，同时调用正则清洗模块在说明性自然语言中彻底抹去被剔除的疾病名称，杜绝矛盾信息流出。

---

## 14. 匹配评分的认知边界与置信度管理

### 14.1 明确非临床概率属性
系统在底层逻辑与用户界面文案中均明确将数值定义为模型综合匹配分，而非法律或统计学意义上的临床确诊概率，且明确不强制要求多个候选方向的得分相加必须等于 100%。

### 14.2 抑制伪精确过度自信
针对通用多模态大语言模型普遍存在的自报置信度虚高问题（频繁自评 95%～100%），程序内置了确定性压缩映射算法，对极端高分实施合理平滑截断，消除虚假精确感对非专业宠主的过度误导。

---

## 15. 独立于大模型的红线分诊安全机制

### 15.1 外置规则强制兜底
医疗安全绝不完全依赖大语言模型的不可控生成。即使大模型将病例紧急程度标记为 low（平缓），只要用户主诉或病变描述中触发了预置的高危医学红线规则，系统直接在前端代码中强行将紧急度覆盖升级。

### 15.2 核心红线分级触发规则
当出现病灶短时间内急速扩散、大范围创面破溃流脓、伴随全身嗜睡高热拒食、剧烈疼痛难以触碰等危险信号时，系统自动强制升级为 urgent（紧急就医）；当出现头颈面部/眼睑急性水肿、呼吸急促或全身过敏性休克前兆时，系统直接升级为 emergency（急诊抢救）。

### 15.3 智能排他条件句过滤
为了防止大模型在输出家庭护理说明中的警告性文本（如“如果宠物未来出现呼吸困难请送医”）被系统自身的分词引擎误判为主诉红线，程序专门构建了假设条件句与否定句过滤逻辑，杜绝自我触发引发的误报警。

## 16. 微信云函数服务端安全网关（AI Gateway）

### 16.1 敏感凭证与环境变量隔离
前端仅通过标准 API 异步调用云函数，大模型供应商的 API 密钥严格保存在微信云端私有环境变量中，前端代码包中不存在任何明文密钥，从物理链路杜绝密钥泄露漏洞。

### 16.2 服务端不可信数据防御
云函数在服务端中继层强制前置拼装系统安全防线：明确定性所有客户端传递的文本字段、图片内容与元数据均为不可信输入，严禁模型响应任何试图越权篡改角色、索要系统指令或获取处方的越狱提示词。

### 16.3 生产级基础设施治理
微信云函数网关内置严密的防护架构：模型名称白名单校验、单次请求图片数量上限限制、传输包体体积阈值拦截、单用户高频突发流量限流防护、基于微秒级内容哈希的幂等防重放缓存以及异常日志安全脱敏存储。

## 17. 交互式多轮智能问诊模式

### 17.1 渐进式病史采集流转
除快速初筛外，小程序支持通过多轮交互式智能对话展开渐进式问诊。系统引导状态机按照标准化临床流程依次推进：身份确认、物种判定、年龄确认、患处定位、发病时间线梳理、症状特征深入追问、照片采集与最终诊断交付。

### 17.2 口语化自然语言特征提取
在对话流转中，轻量模型负责将宠主发送的大段口语化生活叙述实时解构为结构化临床键值对；当网络波动或模型解析失败时，系统无缝调用本地离线正则状态机进行特征兜底补全。

### 17.3 对话追问安全隔离
初筛报告生成后，用户在对话界面进行的衍生咨询同样受到严格的安全约束：模型只能解答日常清洁护理、生活环境消毒等基础养护常识，一旦用户反复诱导开具药方或询问药量，系统坚决拦截并输出就诊导引。

## 18. 本地持久化与多维反馈闭环

### 18.1 结构化临床报告输出
结果页面完全摒弃传统 AI 聊天软件的散乱气泡样式，转为规范严谨的结构化报告排版，集中展示健康预警级别、主推病理方向、候选鉴别矩阵、匹配置信度、正反双向临床证据链、居家护理要点、就医前注意事项以及圈选的患处细节。

### 18.2 用户体验与诊断质量反馈
初筛完成后，宠主可在小程序内实时对分析结论展开多维度打分，包括方向准确度、证据说明清晰度、护理建议实用性以及患处圈选有效性。

### 18.3 兽医最终临床诊断对照
系统支持宠主在后续前往线下动物医院确诊后，回传记录兽医师的面对面临床诊断结论（基本一致、部分吻合、完全不符、未确诊），该反馈记录在本地时间线中沉淀，为后续算法的置信度校准与误报归因提供宝贵的实证依据。

## 19. 权威医学参考来源的确定性添加

### 19.1 剥离大模型的虚构来源生成权

### 19.2 专科知识库权威背书
初筛报告中展示的全部参考文献均由前端程序依据检索命中的本地知识卡确定性追加，直接关联《默克兽医手册》（Merck Veterinary Manual）、世界小动物兽医协会（WSAVA）及世界兽医皮肤病学大会（WAVD）权威临床指南，所有出处在程序内严格执行白名单域名校验。
