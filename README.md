# VetAI · 宠物皮肤病多模态 AI 初筛小程序

面向犬猫家庭的宠物皮肤病院前初筛、客观形态解构与就诊导引微信小程序。基于微信小程序原生框架开发，后端采用微信云函数代理通义千问多模态大模型，结合本地兽医皮肤病规则知识库（65 张专科疾病卡）与双模型并行编排架构，提供秒级病灶初筛、智能问诊、结构化报告与多宠物本地健康档案管理。

---

## 核心定位与设计原则

- **客观形态解构优先**：聚焦于识别并提取图像中肉眼可见的原发与继发皮损形态（如红斑、丘疹、鳞屑、结痂、脱毛等 10 类标准术语），而非越界给出法律意义上的疾病确诊。
- **坚守医疗安全红线**：全链路内置强制安全护栏，严禁输出处方药名称、用药剂量、调药方案或确诊断言；低质模糊图像强制弃答拦截，引导宠主规范重拍或线下就诊。
- **用户隐私与数据最小化**：全量问诊记录、患宠档案及结构化历史报告全部保存在手机端本地存储（`wx.setStorageSync`），敏感医疗图像不落盘公网服务器，开发者端不收集宠主私有医疗影像。

## 核心技术架构

### 1. 双模型并行诊断编排（Parallel Orchestration）
初筛调用发起时，云函数同时并行触发两条推理通道：
- **视觉预检轻量通道（Qwen3.6-Flash）**：负责图像质控（清晰度与可诊断性评分）、10 类受控形态特征标注，并自动分流非皮肤体表（如单纯口腔黏膜、眼结膜病变）；
- **完整诊断推理通道（Qwen3.7-Plus）**：负责结合宠主填写的品种、年龄、病史与主诉进行深度鉴别诊断分析、鉴别矩阵推演与护理建议生成；
- **视觉 RAG 快速路径（Vision-RAG Fast Path）**：当预检提取特征强命中本地知识库高置信度条目（匹配分值 ≥ 8、核心特征数 ≥ 2、Top2 间隔 ≥ 3 且满足组合特征规则）时，系统可在 3～5 秒内直接装配生成预检初筛报告，无需等待大模型完整链路完成，大幅提升典型病例的响应时效。

### 2. 本地兽医专科规则知识库（Domain-Specific RAG）
- **65 张小动物皮肤病专科知识卡**：覆盖犬专属（23 种）、猫专属（17 种）及犬猫通用（25 种）常见皮肤疾病；
- **细粒度多维加权**：涵盖发病急缓、典型发病部位、原发/继发视觉皮损、特殊病史关联词及强排他规则；
- **语义归一与特征组合（Combo）**：内置口语化主诉归一字典与 25 组高置信度特征组合规则（如“圆形脱毛＋鳞屑断毛”），通过多探针行为测试抑制“小疙瘩”等非专业主诉误判为恶性肿块的偏置。

### 3. 多层容错与安全护栏（Safety Guardrails）
- **前置质控拦截**：若图片过暗、过曝、毛发严重遮挡或病损可见度评分低于 40，触发主动拒答并向用户说明原因；
- **5 层 JSON 容错解析**：针对大语言模型输出的 Markdown 代码块包裹、尾部截断、单双引号混用等非标语法提供层级清洗，保障端侧渲染零崩溃；
- **规范化校准清洗**：自动重算知识库归因得分，对大模型诊断结果实施置信度校准与红线关键词清退。

```text
vetai-complete2/

│   ├── detail/             # 档案时间线：单宠患处病程记录与追踪
│   ├── profile/            # 宠物档案管理：多宠物资料与档案卡
│   └── user/               # 个人中心：数据概览、使用记录与本地空间管理
├── utils/                  # 核心业务逻辑与算法层

│   ├── chatDoctor.js       # 对话问诊有限状态机与意图抽取
│   ├── kb.js               # 本地皮肤病知识库（65 张疾病卡与加权检索）
│   ├── knowledge.js        # 医疗红线规则库与紧急度升级判定
│   ├── image.js            # 图像预处理、压缩与 ROI 裁剪
│   ├── lesion.js           # 患处圈选与几何坐标计算
│   ├── storage.js          # 本地持久化隔离存储（多空间与宠物档案隔离）
│   ├── config.js           # 系统环境与功能开关配置
│   └── analytics.js        # 本地行为埋点与会话链路监控
├── cloudfunctions/         # 服务端微信云函数
│   └── diagnose/           # 统一代理网关：三阶段代理、幂等去重与限流配额
├── tests/                  # 自动化测试套件（11 个零依赖纯 Node.js 测试脚本）
├── evaluation/             # 评估与探针工具链
│   └── tools/              # 知识库审计脚本（kb_audit.js）与主诉召回探针（recall_probe.js）
├── project.config.json     # 微信小程序开发与分包构建配置文件
└── package.json            # 测试与辅助构建依赖
```

## 本地开发与测试

本项目前端代码严格遵循原生 JavaScript ES5 规范（使用 `var`，避免 ES6+ 特性及外部框架），无需复杂的打包编译流程，可直接在微信开发者工具中预览与调试。

### 1. 运行本地自动化测试套件

项目内置完备的质量回归测试体系，涵盖目录结构、本地存储隔离、知识库逻辑、诊断编排容错、提示词契约、状态机以及云函数模拟测试，无需依赖外部网络或真实 API Key：

```bash
# 执行全部 11 个自动化测试脚本 + 知识库行为审计 + 24 条真实口语主诉召回探测
npm test
```

### 2. 独立执行专科专项审计

```bash
# 运行知识库结构完整性与 10 大行为探针审计
npm run audit:kb

# 运行真实口语主诉召回率探测（评测纯文本与图文复合召回）
npm run probe:recall
```

### 3. 部署微信云函数

云函数源码位于 `cloudfunctions/diagnose/`：
1. 打开**微信开发者工具**，右键点击 `cloudfunctions/diagnose` 目录；
2. 选择“当前环境”并点击“上传并部署：所有文件”；
3. 在微信云开发控制台中配置环境变量（如 `PROMPT_VERSIONS`、`DAILY_QUOTA` 等参数，模型调用密钥配置在云端环境变量中，前端代码不暴露任何密钥）。

## 编码规范与发布注意事项

- **代码风格**：前端业务逻辑统一采用 ES5 风格书写，历史问题修复统一在代码注释中以 `BUG-编号` 标明对应上下文；
- **敏感配置保护**：`utils/config.js` 中的 `QWEN_API_KEY` 保持为空，全量大模型 API 调用必须经由云函数在服务端闭环完成；
- **分包体积控制**：微信小程序主包上限为 2048KB。`project.config.json` 中的 `packOptions.ignore` 已将 `evaluation/`、`tests/`、`node_modules/` 以及文档文件加入排除列表，新增大型资源文件时需核查打包体积（主包体积维持在 650KB 以内）；
- **用户文案规范**：面向宠物主人的前端交互界面严禁出现“知识库”“RAG 检索”“提示词”“向量匹配”等底层内部工程词汇，保持通俗、平实、富有同理心的动物医学交互语态。
