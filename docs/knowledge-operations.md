# 知识库证据、评测与版本维护

必须遵守的维护规则统一见根目录 [AGENTS.md](../AGENTS.md)；本文件说明具体操作、现有覆盖范围和工具边界。调整工具或流程时同步更新这两处，避免规则与实现脱节。

现有69张疾病卡、规则分数及默认检索策略继续保留。首批证据台账位于 `knowledge/evidence-ledger.json`，以犬猫反复瘙痒中的食物因素与环境过敏鉴别为试点。它补充逐条出处，不改写历史来源，也不把项目组整体复核转称为兽医签署。

## 证据台账

每条记录包含卡片ID、字段、原始片段、字段哈希、原文页码/章节、适用物种与条件、限制、核验人员和记录历史。原文仅保存短定位片段，完整内容通过来源链接访问。

- `source_verified`：本次已对照原文支持所列结论；核验人员为 Codex，角色为资料比对。
- `partial_support`：原文只支持带条件的说法，不能为原字段全部内容背书。
- `pending`：尚未完成该论断的原文核验。

本批11条记录覆盖2张卡：8条有原文支持，2条部分支持，1条待补证。其余卡及字段不因此自动获得已核验状态。原有 `evaluation/config/claim_source_registry.json` 继续保存字段级登记；新增台账提供片段级定位和适用条件，两者均参与测试。

`field_sha256` 是当前卡片字段 JSON 序列化值的 SHA-256；`evidence_sha256` 是引用的原文定位与来源元数据组合哈希。字段、来源版本或原文定位变化会使核验失效。重新对照来源后，更新实际审核记录与哈希，禁止为了让检查通过而无核验地重算哈希。

检索结果携带 `evidenceBindings`，完整模型的参考上下文包含结论、适用条件、限制和核验角色。来源区优先提供已核验条目的具体PDF页码。原文支持的是知识结论，并不证明当前病例符合该结论。

## 评测题库与检索策略

题库 `evaluation/datasets/retrieval_scenarios.json` 独立于运行实现与旧24例探针保存，新写24题，六类场景各4题：常见问题、口语表达、否定、多部位、证据冲突、无法回答。它是本次实现者编写的合成工程题，已经在本轮开发中接触，不是独立专家标注或临床外部验证。

```sh
npm run audit:evidence
npm run eval:retrieval
npm test
```

同一题库、同一输入比较：

| 策略 | 行为 |
|---|---|
| rules | 当前规则检索，默认保留 |
| bm25 | 扩大规则准入的候选，再用中文双字词频检索排序 |
| hybrid_unscoped | 规则排名与BM25排名做RRF融合，用于消融对照 |
| hybrid | 同上，额外保留多部位的规则代表候选，避免另一处病灶被挤掉 |

这是“规则＋关键词”的本地混合检索，没有向量模型或外部API。所有实验候选沿用现有物种、否定、证据与部位准入；因此词频排序不能找回所有被规则漏掉的口语表达。混合结果标记不能触发快速报告，两处快路径判定均显式检查该标记。

本批结果：规则完整覆盖22/24题；BM25为19/24；未保留部位覆盖的混合为20/24；加入覆盖保护后为22/24。6道无候选题各策略均通过。当前没有证据说明混合整体优于原规则，因此保持规则默认。

尚未通过的两题原样保留：季节性瘙痒题未完整召回预期的两个参考方向；“毛缺了一小圈”等表达未召回。它们是后续开发线索，不能删掉以提升成绩。所有分数为参考卡检索指标，不是诊断准确率或模型临床弃答率。

JSON报告包含每题结果、输入哈希、实现哈希、场景分层、执行失败和差异；Markdown报告用于阅读。不同版本题库的成绩不可直接当作策略提升。允许重复评测，修订升版本并保留旧报告。

## 发布与增量更新

每批完成核验后：

1. 修改卡片或台账，记录实际审核过程与适用范围。
   修改台账或发布新版本后执行 `npm run knowledge:bundle`，重新生成 `utils/knowledgeBundle.js`（小程序 require 不支持 .json，运行时由它提供台账与版本号）。
2. `npm run knowledge:plan -- --from 上一版本ID` 查看变更文件、受影响结论与卡片。
3. 运行证据审计、同题库对照和完整测试；出现资料冲突则保留状态和限制。
4. `npm run knowledge:publish -- --id 新版本ID --reason "本批核验与修改说明"` 保存新版本包，并更新 `knowledge/current-release.json`。
5. 在微信开发者工具重新编译、预览并按现有发布流程上线。命令只保存本地知识版本，不发布微信小程序。

版本包保存 `utils/*.js`、知识JSON及评测题库的精确内容与哈希；每个ID只能创建一次。发布时强制校验证据绑定；同一工作目录只允许一个发布/恢复操作。规则分数、疾病卡和证据版本分别记录。

本地BM25索引在模块加载时建立；增量计划定位需要核验的内容，新版本重新启动/编译后重建索引。目前69张卡采用整库重建，不引入持久向量索引服务。

## 回退

```sh
npm run knowledge:status
npm run knowledge:restore -- --id 目标版本ID
```

回退先校验版本包完整性、在临时目录检查目标知识，再保存当前字节备份后恢复。工作区存在未发布修改时拒绝覆盖，应先把需要保留的修改核验并发布为检查点。不能用回退绕过来源或字段失效检查。

回退范围是版本包列出的知识运行文件与题库，不是整个Git仓库。测试、操作工具和界面文件不在恢复范围。恢复后重新运行测试、重启/编译小程序；外部云端版本不会自动改变。首次发布建立恢复锚点，后续各批次均可选择历史ID恢复。

## 监控

```sh
npm run knowledge:monitor
npm run knowledge:monitor -- --samples /绝对路径/本地样本.json
```

第一条检查文件与发布记录是否一致、证据是否失效、来源是否到复查日期。第二条额外读取 `analytics.getSamples('knowledgeRetrieval')` 导出的样本数组，按版本与策略汇总空结果比例、失败数、耗时P95及已绑定结论数量。源资料可达性和正文变化需复查原文并更新台账；本命令不假装已在线检查网页。

小程序已有本地埋点通道会保存最近最多300条记录，仅含版本、计数、耗时与失败标记，不保存主诉、图片、身份或疾病名称。空结果比例用于观察趋势，不单独视为错误；当前只对执行失败、文件漂移、来源过期和样本足够时的50毫秒本地检索预算告警。它不是全量线上监控，未配置远程上报或定时任务。
