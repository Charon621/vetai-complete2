# RAG 主流程本地试用与恢复

报告界面沿用原有拍照报告和对话简版报告的布局。2026-10-11 根据用户要求停用替换页面的 assessment-report 组件，新结果通过 `utils/reportPresentation.js` 接入原有结论卡、照片、建议、判断依据和反馈。数据适配只影响展示，不改写历史记录；进一步分析和重试入口保留在原页面底部。本次界面恢复版本为 `kb-2026.10.11-rag.5`。

GitHub 同步版本为 `kb-2026.10.11-rag.6`：将受管理源码与 Git 暂存字节的换行对齐后建立新本地版本，避免其他电脑拉取后出现哈希漂移；业务内容及报告布局不变。

以下新观察流程描述仅适用于显式 `guided` 模式及其已保存记录。该模式把逐图观察转为可追溯的事实，再用已有疾病卡提供核对方向。结果分为排序候选、仅形态、无法判断；新结果没有诊断百分比。候选、支持、反证、待补充信息和参考描述分别保存、展示。未知风险不会显示为安全。

## 运行模式与请求

唯一开关是 `utils/config.js` 的 `RAG_WORKFLOW_MODE`。2026-10-12 按用户要求恢复 `legacy` 默认值，重新使用并行预检与完整诊断、原快路径门槛和原报告字段。`guided` 保留为显式试验模式，不作为新问诊的默认入口。`shadow` 沿用旧请求和用户输出，仅在显式离线 trace 中核对本地新排序。`guided` 在开启知识初筛时先发一次 `vision-precheck`。观察成功、照片可用但没有合格候选时，沿同一输入快照自动发一次 `full-diagnosis`；已经有候选、照片不可辨认、技术失败或明确急症时不追加自动请求。每阶段不自动重试。用户也可在历史报告点击继续完整分析。关闭知识初筛继续使用原完整分析入口。

新客户端启用 guided 前必须先部署并核对 `cloudfunctions/diagnose/index.js`。新增 `vetai-rag-observation-v1` 白名单，逐图观察预算上限 1400 tokens；旧观察预算仍为 700。旧 `vetai-derm-v2.0.0`、`vetai-derm-v2.0.1` 继续兼容。2026-10-11 已增量部署 `diagnose/index.js` 到配置中的云环境，客户端默认开关随后切为 guided；微信小程序正式版上传另行执行。

`case-facts-v1` 保持不变。新增证据、观察、初筛、概念、检索 profile、排序策略、提示词和知识发布版本分别保留。概念词只取既有受控词及严格同义；主人原话另认 `kb.expandQueryFacts` 的口语桥接（仅当前、肯定、宠物本身的同一片段，见下文 2026-10-12）。照片不能产生病史。已发送照片、ROI 父图与未发送照片有独立编号。保存实际送入观察的图片和轻量输入指纹；深化须核对同一照片字节、物种、主诉及快照，不在历史记录中保存 base64。

技术失败不会自动改成照片不清。完整分析失败时保留照片观察和明确重试提示，成功时前置展示综合结论、依据、检查与就医提示；完整模型方向与卡片支持方向分开保存，不伪造百分比。观察阶段技术失败可用保存的原照片重试，写入失败仍保留旧记录。重试保存不重复调用模型，旧记录在新版本写入失败时保留。新版历史写入达到条数或修订上限时明确拒绝，不静默清除旧记录。运行期间切换数据空间或关闭页面，旧回调不能写入新空间。

## 检索与证据边界

`knowledge/retrieval-profiles.json` 由既有卡片字段编译，69 张卡全部覆盖；未核验的条件保持 pending，原来源未知如实记录。没有新增临床知识、角色或因果关系。组合支持只复用旧规则，要求同一作用域的明确事实，最多加一次有限分值。排序分值只用于排序。

## 2026-10-12 快报告点名分级、部位锁定与口语桥接

guided 有候选即直接出报告，原先报告主标题固定取第一候选的病名，纯文字或证据并列时也同样口吻。本批不加调用、不设分数阈值，改为结构规则：

- 点名分级（`ragAssessment.tiers`）：候选须有照片来源、清晰可见、特异的支持证据，且该证据为本组其他候选所无，并且全组只有它满足，才标 `evidenceTier: 'named'`，报告主标题写病名；否则为 `tentative`，主标题写“可能方向待核对”，列出全部方向并提示继续完整分析。旧记录没有该字段时沿用原展示。
- 部位锁定（`ragRetrieval.siteConflict`）：卡片全部部位都能归入身体区域时取区域并集；病灶部位（事实部位，缺失时取表单部位）明确落在其他区域则不进入可交付候选，保留在 pool 并标 `siteConflict`。含头部、面部、躯干、全身等不归区域的部位时不锁定。当前 18 张卡受约束。排序策略版本升为 `rag-rank-v2`。
- 口语桥接（`clinicalConcepts.fromOwnerContext`）：主人原话除字面含概念词外，也接受同一片段经 `kb.expandQueryFacts` 得出的概念（如“黑色小点”→黑色颗粒、“一粒粒”→丘疹）；桥接只认当前、肯定、宠物本身的片段。
- 否定识别（`evidenceScope`）补“没看到/没看见/没发现/看不到/未发现”。

`recall_probe` 测的是 `kb.search(原始主诉)`，不经过上述事实与分组步骤，不能代表线上候选。新增 `npm run probe:guided`（`evaluation/tools/guided_probe.js`）按线上同一组函数运行旧 24 例与检索题库，统计点名、可能方向、无候选、点名正确与点名错误，并含固定回归用例；固定用例同时在 `tests/ragRetrieval.test.js` 断言。withPhoto 通道把人工模拟视觉词按“清晰可见”注入，结果是点名率上限，不是真实模型实测。

已知未解决：照片事实病灶归属为 unknown，与按部位分组的主诉事实分属不同作用域，两类证据不合并打分；只有可能方向时不自动追加完整分析。recall 例 4（色素沉着→日光性皮炎）与例 23（色素脱失→皮肤淋巴瘤）在照片通道仍会点名错误，属卡片证据特异性配置问题，改动前同样出错。
